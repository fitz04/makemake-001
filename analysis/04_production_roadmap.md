### Phase 0: 프리프로덕션 (4주)

**기간:** 4주 (Week 1-4)

**목표:**
GDD V11 통합 문서를 작성하여 14건의 문서 불일치를 해소하고, 케이 캐릭터 시트를 작성하며, 기술 파이프라인을 구축한다.

**산출물 (Deliverables):**
1. **GDD V11 통합 문서** -- 추가설정노트 20251228/20251229를 GDD V10에 병합
   - 발전기 설계 통일 (과염소산염 + 질소 팽창 시스템 채택)
   - D-D 출력 2.1GW로 전문서 통일
   - 레이저 채굴 전력 1GW 확정
   - R-1 로버: 시작 시 완파 -> Act 3 재제작 -> RTG 7kW 독립 전원
   - RTG 반감기: 기본 모드 없음, 하드 모드 적용 (최소 출력 하한 0.5kW)
   - Z-Pinch: D-D 비상 모드 점화용 확정
   - 오리온 프로젝트 엔딩: 완전 삭제
2. **케이 캐릭터 시트** -- 성격 특성 5개, 말투 가이드, Act별 호칭 변화, 감정 트리거 정의
3. **기술 환경 구축 완료**
   - Godot 4.6 Double Precision 커스텀 빌드 + VoxelTools Module 빌드
   - Git 리포지토리 + LFS 설정 (에셋 관리)
   - CI/CD 파이프라인 (자동 빌드)
4. **에셋 파이프라인 검증** -- Unity 에셋 FBX 변환 워크플로우, Sketchfab .gltf 직접 임포트 테스트
5. **Act별 색상 팔레트 레퍼런스 시트** (컨셉 아트 수준)

**성공 기준 (Definition of Done):**
- [ ] GDD V11 문서에서 Critical 불일치 3건, Major 불일치 3건 전부 해소
- [ ] Godot 4.6 DP 빌드에서 VoxelLodTerrain이 정상 동작하는 빈 프로젝트 실행 확인
- [ ] 케이 캐릭터 시트 완성 (A4 2장 분량 이상)
- [ ] Git 리포에 첫 커밋 완료, 빌드 파이프라인 테스트 성공

**의존성:** 없음 (첫 페이즈)

### Phase 1: 지형 프로토타입 (4주)

**기간:** 4주 (Week 5-8)

**목표:**
구형 복셀 행성을 생성하고, 후처리 파이프라인을 구축하며, 800km 스케일의 기술적 실현 가능성을 검증한다. 이 게임의 최우선 가치인 '비주얼 분위기'를 프로토타입 수준에서 증명한다.

**산출물 (Deliverables):**
1. **구형 복셀 행성** (VoxelLodTerrain + 구면 노이즈)
   - 800km 직경 테스트 (실패 시 80km 대안)
   - 톨린(붉은 먼지) + 질소 얼음(푸른빛) + 메탄 얼음(호박색) 텍스처 블렌딩
   - Triplanar Mapping 셰이더
   - 높이/경사도 기반 텍스처 분류
2. **Origin Shifting 구현** (solar_system_demo 참조)
3. **후처리 파이프라인 v1**
   - SSAO (강도 높음)
   - ACES Filmic 톤매핑
   - 색보정 (차가운 외부 / 따뜻한 내부)
   - Film Grain (약간)
   - Bloom (임계치 높음)
   - Vignette (헬멧 시야 암시)
4. **스카이박스** (HDR 은하수 파노라마 + 약한 태양광)
5. **그림자 설정** (shadow_blur = 0, 진공의 날카로운 명암)
6. **스케일 검증 보고서** -- 400km 반경 테스트 결과, FPS/메모리/LOD 안정성 데이터

**성공 기준 (Definition of Done):**
- [ ] 구형 행성 위에 서서 지평선을 바라볼 수 있음 (1인칭 카메라)
- [ ] 3가지 이상 지형 바이옴 텍스처가 블렌딩되어 보임
- [ ] 후처리 적용 상태에서 60FPS 이상 유지 (GTX 1060 급)
- [ ] "카이퍼벨트 왜소행성"의 분위기가 스크린샷만으로 전달됨
- [ ] 스케일 결정 확정 (800km / 80km / 기타)

**의존성:** Phase 0 완료 (Godot DP 빌드)

**리스크 게이트:** 이 페이즈에서 800km 스케일이 불가능하면, 80km로 축소 결정. 80km도 불가능하면 Unity + 커스텀 복셀 엔진으로 엔진 전환 검토 (Phase 0으로 복귀, +8주 추가).

### Phase 2: 코어 루프 프로토타입 (6주)

**기간:** 6주 (Week 9-14)

**목표:**
게임의 핵심 루프(이동 -> 채굴 -> 제련 -> 제작 -> 전력 증가)를 최소 수준으로 구현하여, 재미의 핵심을 검증한다.

**산출물 (Deliverables):**
1. **1인칭 캐릭터 컨트롤러**
   - 0.06g 저중력 물리 (점프 시 높이 뛰고 천천히 착지)
   - 관성 기반 미끄러짐
   - 구면 중력 벡터 (행성 표면 어디서든 중심 방향)
2. **복셀 채굴 시스템**
   - edit_box() 기반 지형 변형 (핸드 드릴)
   - 자원 드롭 (채굴 시 아이템 생성)
   - 자원 종류: 물 얼음, 질소 얼음, 메탄 얼음, 레골리스, 황동광
3. **인벤토리 시스템 (기본)**
   - 아이템 픽업 / 드롭 / 스택
   - 무게 시스템 (저중력 고려)
4. **제작 시스템 (기본)**
   - Mk.0 워크벤치: 레시피 기반 아이템 조합
   - 제작 UI (레시피 목록, 재료 체크, 진행 바)
5. **전력 시스템 (기본)**
   - RTG (1.5kW) -> 메탄 발전기 (50kW) 2단계
   - 전력 소비/공급 밸런스 UI
   - 전력 부족 시 기계 정지
6. **기본 생존 HUD**
   - 산소 게이지
   - 허기 게이지
   - 사기 게이지
   - 전력 현황

**성공 기준 (Definition of Done):**
- [ ] 얼음을 캐서 전해조에 넣고 산소를 생산하는 한 사이클이 동작
- [ ] RTG -> 메탄 발전기 전환 과정이 플레이 가능
- [ ] Mk.0 워크벤치에서 3개 이상 아이템 제작 가능
- [ ] 산소 고갈 시 사망 -> 재시작 동작
- [ ] 30분 연속 플레이 테스트에서 "한 번 더" 하고 싶은 느낌 확인

**의존성:** Phase 1 완료 (지형 위에 캐릭터를 올릴 수 있어야 함)

### Phase 3: Act 1 완성 (8주)

**기간:** 8주 (Week 15-22)

**목표:**
튜토리얼 역할을 하는 Act 1(최초 48시간, 플레이 시간 2-3시간)을 완성한다. 5대 생존 위기를 순차적으로 해결하는 경험을 구현한다.

**산출물 (Deliverables):**
1. **추락 거주구 레벨 디자인**
   - 내부: 파손된 거주구 메시 (하이브리드 전략 1 적용)
   - 외부: 잔해 필드 (RTG, 로봇 팔, 선반 등 상호작용 오브젝트)
   - 복셀 기초 평탄화 시스템
2. **5대 생존 위기 시퀀스**
   - 위기 1: 헬멧 파손 (5분 타이머 + 덕트 테이프)
   - 위기 2: 거주구 산소 (RTG 회수 + 비상 전해조)
   - 위기 3: 수소 폭발 (배출 호스 퍼즐)
   - 위기 4: 공기 혼합 (질소 얼음 탐색 + 분광기)
   - 위기 5: CO2 중독 (Mk.0 프린터 조립 + 스크러버)
3. **AI 케이 대화 시스템 v1**
   - 이벤트 트리거 기반 대사 출력
   - 자막 UI
   - Act 1 전용 대사 스크립트 (부활 이벤트 포함)
   - "첫 침묵" -> "부팅음" -> "케이 목소리" 사운드 시퀀스
4. **분광기 도구** (자원 탐색 UI)
5. **에어락 시스템** (내부/외부 전환 + 색보정 점진 변화)
6. **사망/재시작 시스템** (위기별 사망 조건 + 체크포인트)

**성공 기준 (Definition of Done):**
- [ ] 신규 플레이어가 2-3시간 내에 Act 1을 완료할 수 있음
- [ ] 5대 위기 모두 작동하며, 각 위기 해결 시 성취감이 있음
- [ ] 케이의 "주인님... 전력이 들어왔어요" 이벤트에서 감정적 반응 유발
- [ ] Act 1 종료 시 RTG 1.5kW + Mk.0 프린터 + 기본 생존 완성 상태
- [ ] 5명 이상 외부 테스터에게 플레이 테스트 (첫인상 피드백 수집)

**의존성:** Phase 2 완료 (코어 루프 기반)

### Phase 4: Act 2 완성 (10주)

**기간:** 10주 (Week 23-32)

**목표:**
산업 기반 구축의 핵심 구간인 Act 2(플레이 시간 5-7시간)를 완성한다. 메탄 발전기 건설, 식량 위기, AI 시각 획득이라는 3대 감정 비트를 구현한다.

**산출물 (Deliverables):**
1. **메탄 발전기 건설 퀘스트 라인**
   - 과염소산염 + 메탄 하이드레이트 채굴
   - 소결 세라믹 벽돌 제작 (전기로 미니게임)
   - 원심 주조 터빈 날개 (타이밍 미니게임)
   - 용접 조립 (방패 방어 미니게임)
   - 발전기 설치 + 가동 이벤트
2. **MRE 오염 이벤트 + 식량 위기**
   - 사바티에 반응기 수리 퀘스트
   - 포름오스 반응로 제작 (최초 식량)
   - 국소 배기 장치 (안전 공학)
   - 허기/사기 시스템 본격 가동
   - [역겨움] 디버프 중첩 시스템
3. **셀레늄 발견 + AI 광센서 이벤트**
   - 구리 제련 공정 (배소 -> 용융 -> 원심분리)
   - 셀레늄 발견 "와우 모먼트"
   - 광센서 제작 -> AI 시각 획득
   - "빛이... 보여요!" 연출 (사운드 + 시각 효과)
4. **Mk.1 금속 프린터**
   - 고온 전기로 (35kW)
   - WAAM 방식 프린팅 UI
   - AI X,Z축 자동 / 플레이어 Y축 제어
5. **기지 건설 시스템 v1**
   - 복셀 기초 평탄화 (edit_box)
   - 메시 기반 건물 배치
   - 구면 정렬 (RayCast 기반)
   - 보호 구역 시스템
6. **사운드 디자인 v1**
   - 외부: 호흡 + 심장박동 + 도구 진동
   - 내부: 생명유지 장치 윙윙 + 기계 소음
   - 케이: 금속적 음질 (Act 2에서 깨끗해짐)

**성공 기준 (Definition of Done):**
- [ ] Act 1 -> Act 2 자연스러운 전환 (전력 한계 체감 -> 발전기 동기 부여)
- [ ] 메탄 발전기 50kW 가동 시 "해방감"
- [ ] MRE 오염 -> 식량 위기 -> 포름오스 반응의 긴장-안도 사이클
- [ ] "빛이... 보여요!" 이벤트가 게임 내 최고 감동 순간 중 하나로 작동
- [ ] 화학 공정 UI가 "교육적이되 지루하지 않은" 밸런스 달성
- [ ] Act 2 종료 시: 50kW + Mk.1 프린터 + 식량 자급 + AI 시각 상태

**의존성:** Phase 3 완료

### Phase 5: Act 3 완성 (10주)

**기간:** 10주 (Week 33-42)

**목표:**
자동화와 최적화의 핵심 구간인 Act 3(플레이 시간 5-7시간)를 완성한다. "귀찮음 -> 자동화 -> 해방감" 루프의 카타르시스를 구현한다. Living Lode 첫 조우를 서사적 복선으로 배치한다.

**산출물 (Deliverables):**
1. **물리적 채굴 고도화**
   - 개량형 드릴 Mk.2 (텅스텐 카바이드 비트)
   - 폭파 채굴 시스템 (질산암모늄 + 기폭 + 원격 폭파)
   - 지하 동굴 생성 (VoxelGenerator 템플릿 합성, 전략 2)
2. **전력 이중화 (~200kW)**
   - 수소 연료전지 시스템 (+50kW)
   - 메탄 터빈 개량 (50kW -> 100kW)
   - 전력 분배 UI 개선
3. **Mk.2 정밀 프린터**
   - SLM 방식 프린팅
   - AI 완전 자동 제어
   - 고급 부품 레시피 (초전도 코일, AI 코어 등)
4. **자동화 시스템**
   - R-1 로버 (4륜/6륜, RTG 7kW) -- 6족 보행은 MVP 후 검토
   - AI 경로 탐색 + 자동 채굴 임무
   - 컨베이어/파이프 배치 시스템
   - 자동 분류기 + 저장 사일로
5. **식품 자동화**
   - 우레이-밀러 합성 아미노산 (Tier 1)
   - 배양육 스테이크 (Tier 2) -- [만성적 혐오] 치료 효과 통합
   - 사기 시스템 밸런싱
6. **Living Lode 첫 조우**
   - 채굴 중 이상한 결정 발견 이벤트
   - 케이의 "살아있는 것 같아요" 대사
   - 이후 Act 4까지 간헐적 연구 보고 (복선)
7. **서사적 위기 이벤트** (Act 2-3 경계)
   - 예: 발전기 고장 -> 일시적 RTG 전력 퇴행 -> 케이 약화 -> 전력 이중화 동기

**성공 기준 (Definition of Done):**
- [ ] 수동 채굴 -> 로버 자동 채굴 전환 시 명확한 "해방감"
- [ ] ~200kW 전력 안정 상태에서 공장 라인이 시각적으로 인상적
- [ ] Living Lode 첫 조우가 Act 4의 복선으로 자연스럽게 작동
- [ ] 전체 Act 3을 5-7시간 내 소화 가능 (각 Phase 40-60분)

## 5. 기술 부채 관리 전략

### 5.1 "지금 해도 되는 것" (프로토타입에서 바로 프로덕션 코드로)

이 항목들은 처음부터 제대로 만들어도 시간이 많이 들지 않으며, 나중에 바꾸면 비용이 크게 증가한다.

| 항목 | 근거 | 적용 시점 |
|------|------|----------|
| **프로젝트 구조 / 폴더 체계** | 나중에 리팩토링하면 모든 참조가 깨짐 | Phase 0 |
| **씬 트리 아키텍처** | Godot의 씬 트리 설계는 프로젝트 전체에 영향 | Phase 0 |
| **자원(Resource) 데이터 구조** | 아이템/레시피/자원 정의는 초기에 확장 가능한 구조로 | Phase 2 |
| **세이브/로드 시스템 기본 설계** | 나중에 끼워 넣기 어려움. 직렬화 구조는 초기 설계 필수 | Phase 2 |
| **입력 매핑 (Input Map)** | 리매핑 지원 고려한 설계 | Phase 2 |
| **신호(Signal) 버스 패턴** | Godot의 Signal 기반 이벤트 시스템. 글로벌 이벤트 버스 초기 도입 | Phase 2 |
| **복셀 텍스처링 셰이더** | Triplanar + 바이옴 블렌딩은 교체 비용이 높음 | Phase 1 |

### 5.2 "나중에 해야 하는 것" (프로토타입에서는 간략히, 프로덕션에서 리팩토링)

이 항목들은 프로토타입 단계에서 완성도를 높이면 오히려 이터레이션이 느려진다. 기능 검증 후 리팩토링한다.

| 항목 | 프로토타입 수준 | 프로덕션 수준 | 리팩토링 시점 |
|------|---------------|-------------|-------------|
| **UI/UX** | 프로그래머 아트 (기본 Control 노드) | 외주 UI 스킨 적용 + 애니메이션 | Phase 5-6 |
| **AI 케이 대화 시스템** | 하드코딩 트리거 + 텍스트 | 데이터 드리븐 대화 시스템 (JSON/CSV) + 현지화 지원 | Phase 4 시작 시 |
| **사운드 시스템** | 플레이스홀더 효과음 | 전문 사운드 + FMOD/Wwise 통합 검토 | Phase 5 |
| **화학 공정 UI** | 텍스트 기반 레시피 목록 | 시각적 공정 다이어그램 + 실시간 온도/압력 게이지 | Phase 4-5 |
| **로버 AI** | 단순 목표점 이동 | A* 경로 탐색 + 장애물 회피 + 자동 충전 | Phase 5 |
| **후처리 세밀 조정** | 기본 환경 설정 1세트 | Act별/상황별 동적 전환 (사기, 산소, 실내외) | Phase 6-7 |
| **최적화** | "동작하면 됨" | 프로파일링 기반 체계적 최적화 | Phase 7 |
| **에러 처리 / 예외 상황** | 크래시 허용 | 그레이스풀 실패 + 자동 복구 | Phase 7 |

### 5.3 리팩토링 마일포스트

프로토타입 코드가 프로덕션 코드로 전환되어야 하는 핵심 시점:

**리팩토링 1: Phase 3 시작 시 (Week 15)**
- 대상: Phase 2에서 만든 코어 루프 코드
- 범위:
  - 인벤토리 시스템 데이터 구조 정리 (딕셔너리 -> 커스텀 Resource)
  - 전력 시스템 노드 구조 확립 (PowerGrid 글로벌 매니저)
  - 제작 시스템 레시피 데이터 외부화 (JSON)
- 예상 소요: 1주

**리팩토링 2: Phase 5 시작 시 (Week 33)**
- 대상: Phase 3-4에서 누적된 코드
- 범위:
  - 퀘스트/이벤트 시스템 데이터 드리븐 전환
  - AI 대화 시스템 JSON 기반으로 전환 (현지화 준비)
  - 건물 배치 시스템 모듈화
  - 화학 공정 시스템 일반화 (개별 공정 -> 공통 프레임워크)
- 예상 소요: 1.5주

**리팩토링 3: Phase 7 시작 시 (Week 53)**
- 대상: 전체 코드베이스
- 범위:
  - 사용하지 않는 코드/에셋 정리
  - 성능 핫스팟 리팩토링 (프로파일러 결과 기반)
  - 세이브 시스템 최종 검증 (하위 호환성)
  - 에러 핸들링 강화
- 예상 소요: 1주

### 5.4 기술 부채 허용 원칙

```
프로토타입 단계 (Phase 1-2):
  "동작하면 됨. 코드 품질보다 속도."
  허용: 하드코딩, 매직 넘버, 중복 코드
  금지: 세이브 시스템 설계 미비, 씬 트리 구조 무시

프로덕션 단계 (Phase 3-6):
  "확장 가능해야 함. 새 콘텐츠 추가가 쉬워야 함."
  허용: UI 프로그래머 아트, 플레이스홀더 사운드
  금지: 데이터 하드코딩 (레시피, 대사 등)

폴리시 단계 (Phase 7):
  "버그 없이 안정적이어야 함."
  허용: 없음 (모든 부채 청산)
  금지: 새 기능 추가
```
